# Состояние процесса: `state.json` и `receipt.json`

**[English](agent-state.md)** · **Русский**

История диалога не является основным источником достоверных данных (system of record). Сброс контекста, начало новой сессии или смена модели не должны приводить к потере информации о том, в чем заключается суть изменений, какие решения уже были приняты, а также какие подходы были опробованы, но не дали результата.

Для каждого изменения создаются два файла, размещаемые в директории `openspec/changes/<name>/` и сохраняемые в архиве:

| Файл | Когда записывается | Когда считывается |
|---|---|---|
| `state.json` | перед началом реализации, затем обновляется на границе каждой задачи | **в первую очередь**, при возобновлении работы |
| `receipt.json` | один раз, по завершении работы | при сравнении двух запусков (кем-либо) |

## `state.json`

```json
{
  "change": "add-cache-starter",
  "contract": {
    "goal": "создание единой абстракции именованного кэша (named-cache) взамен двух наборов компонентов Caffeine",
    "output": "реализация cache-spring-boot-starter + перенос настроек безопасности/пользовательских параметров",
    "constraints": [
      "запрет на добавление новых зависимостей в репозиторий для модуля безопасности",
      "соблюдение верхнего предела TTL для безопасности"
    ],
    "done_when": [
      "mvn -q validate",
      "mvn -pl cache-spring-boot-starter -am verify",
      "mvn -pl security-spring-boot-starter -am verify",
      "openspec validate add-cache-starter"
    ]
  },
  "current_task": "3.2",
  "decisions": [
    "по умолчанию — только локальный кэш; возможность использования общего (shared) уровня для отдельных кэшей"
  ],
  "failures": [
    "повторная попытка вытеснения (eviction) из общего кэша: метрики пока отсутствуют"
  ],
  "open_questions": [
    "сохраняется ли сканирование набора ключей (key-set scan) при вызове evict(PrincipalRef)?"
  ],
  "pending_human": []
}
```

Два ключевых свойства делают этот механизм функциональным, а не просто декоративным. В них заключается вся суть подхода: если агент использует этот файл лишь как «черновик» для заметок, он не получает никаких преимуществ от данной системы. ### Блок `contract` создается до внесения первого изменения и в дальнейшем никогда не редактируется

Не «редко редактируется», а **никогда** — за исключением случаев явного изменения области действия (scope), что фиксируется в разделе `decisions` с указанием того, что именно было изменено и почему. Это предотвращает ситуацию, когда задача незаметно подменяется более простой версией, которая формально считается выполненной, но на деле не решает поставленную задачу. Именно так чаще всего происходит, когда работа агента проходит проверку, но затем терпит неудачу в продакшене.

В поле `done_when` содержатся сами команды, а не их описание. Команда `scripts/gate.sh --list <module>` выводит готовый список, который можно просто скопировать и вставить.

### Разделы `decisions` и `failures` работают только на добавление

Их содержимое никогда не перезаписывается, не сокращается и не переупорядочивается. Принятое решение не обсуждается заново в следующей сессии. Зафиксированный случай неудачи не «открывается» снова — в противном случае агент мог бы по ошибке повторить подход, который в предыдущей сессии уже доказал свою неэффективность.

Список `open_questions` — единственный, который может уменьшаться: после получения ответа вопрос переносится в `decisions` вместе с этим ответом. В `pending_human` попадают задачи, которые невозможно выполнить без участия человека; наличие записей в этом списке — сигнал к тому, что нужно остановиться и предоставить отчет, а не пытаться угадать решение.

### Возобновление работы

При возобновлении процесса (имея на руках только название изменения):

1. Считывается файл `openspec/changes/<name>/state.json`. Блок `contract` определяет критерий завершенности («done»); `current_task` указывает, с какого этапа продолжить; а `decisions` и `failures` содержат информацию о том, к чему не следует возвращаться.
2. Из файла `openspec/changes/<name>/tasks.md` извлекается задача, соответствующая `current_task`.
3. Выполняется инициализация индекса кода (через `set_project_path`, `build_deep_index`), после чего работа продолжается.

Больше ничего не требуется. Если на основе этих данных невозможно восстановить контекст работы, значит, в файле состояния чего-то не хватает — добавьте недостающую информацию, вместо того чтобы пытаться восстановить ее из diff-файла. ## Ограниченное количество повторных попыток

Лимит повторных попыток задается здесь, а также в файле `openspec/config.yaml`. Важно отметить, что решение о том, стоит ли предпринимать еще одну попытку, **не** принимается самим агентом:

- **Три попытки на задачу.** Каждая попытка должна приводить к каким-либо заметным изменениям. Повторное выполнение того же самого действия (правки) не считается новой попыткой.
- **После третьей неудачной попытки — остановка.** Информация о возникшей проблеме добавляется в раздел `failures`, при необходимости выставляется флаг `pending_human` (требуется вмешательство человека), после чего формируется отчет.
- **Недопустимо добиваться «успеха» путем снижения стандартов.** Запрещается расширять область изменений, ослаблять правила Checkstyle или ArchUnit, удалять или помечать аннотацией `@Disabled` падающие тесты, а также ограничивать правки только теми частями кода, которые и так проходят проверку. Честный отчет о заблокированной задаче — это полезный результат; «зеленая» сборка, скрывающая проблему, — нет.

Модель выполняет исправление локальной ошибки, но вопрос о том, допустима ли еще одна попытка, находится вне ее компетенции.

## `receipt.json`

Файл создается однократно по завершении работы и сохраняется в архиве. 
```json
{
  "change": "add-cache-starter",
  "model": "claude-opus-5",
  "index_version": "0665e28ffa69a979b74da19c17b7c6d4766df5bba89512de1b0d20448b313552",
  "modules_touched": [
    "cache-spring-boot-starter",
    "security-spring-boot-starter"
  ],
  "gate": {
    "validate": "pass",
    "verify": "pass",
    "openspec_validate": "pass"
  },
  "tests": {
    "added": 14,
    "passed": 212,
    "failed": 0
  },
  "retries": 2,
  "human_corrections": 1,
  "rollback_point": "2071728a1c4d9f0e5b3a7c2d8e6f4a1b9c0d3e5f",
  "unresolved": [
    "evict(PrincipalRef) по-прежнему имеет сложность O(n)"
  ]
}
```

| Поле | Источник данных |
|---|---|
| `model` | модель, на которой выполнялся запуск — причина наличия этого поля |
| `index_version` | `index.freshness.pomSetSha` из файла `project-index.json` |
| `modules_touched` | названия модулей в том виде, в каком они указаны в `project-index.json` |
| `gate` | фактический результат выполнения каждой команды проверки (gate); это не прогноз |
| `retries` | количество повторных попыток |
