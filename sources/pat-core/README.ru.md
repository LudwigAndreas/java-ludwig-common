# pat-core

*[English](README.md) · **Русский***

Формат персонального токена доступа (PAT) и ничего с состоянием: формат на проводе, маскирующий носитель
секрета, дайджест, набор scope для ослабления прав, единственное определение JWT-claim `ludwig_pat`, ответ
интроспекции и константы типов проблем, которыми граница сети отрисовывает отклонённые учётные данные. Без
хранилища, Spring, HTTP и **без зависимостей в репозитории**.

| | |
|---|---|
| Роль | library |
| Зависит от (в репозитории) | ничего |
| Используется | `pat-spring-boot-starter` (выпускает), `security-spring-boot-starter` (проверяет) |
| Поверхности | нет; поставляет `pat-secret-detection.properties` для сканеров секретов |

```
                        pat-core  (0 зависимостей в репозитории)
                         ^      ^
                         |      |
  security-spring-boot-starter  |         <- читает claim, применяет пересечение
          ^         ^           |
          |         |           |
     pat-spring-boot-starter ---+         <- хранит, выпускает, обменивает
```

## Использование

Модуль используют стартеры; сервис редко зависит от него напрямую.

| Тип | Назначение |
|---|---|
| `token.PatSecret` | Сырой секрет в типе, который не печатает себя |
| `token.PatTokens` | Выпуск и разбор `lpat_<keyId>_<secret>_<crc32c>` |
| `token.PatDigest` | SHA-256 и сравнение за постоянное время |
| `token.PatDetection` | Опубликованный шаблон сканера, читаемый из того же файла, что и сканеры |
| `scope.PatAttenuation` | Набор scope и его единственная операция: пересечение |
| `claim.PatClaims` | Единственное определение claim `ludwig_pat` |
| `introspection.PatIntrospectionResponse` | Ответ RFC 7662 сервису, спрашивающему о токене |
| `problem.PatProblemTypes` | Типы проблем и адрес управления, которые отрисовывает **граница сети** |

### Инвариант

PAT - это **ослабление** текущих прав владельца:

```
effective = authoritiesOf(owner, now)  ∩  token.scopes()
```

Никогда не объединение и никогда не снимок на момент выпуска. Права владельца определяются заново на каждый
запрос через `AuthorityLookup`, поэтому отозванная роль перестаёт работать в пределах TTL кэша прав.
`PatAttenuation` не предлагает `union`, `plus`, `grant` или `withAdditional`; тест рефлексией проверяет, что
расширяющего метода нет.

### Имена полей интроспекции

Компоненты `PatIntrospectionResponse` называются `sub`, `aud`, `exp`: без Jackson в classpath (ноль
зависимостей) имена компонентов и есть имена RFC 7662 на проводе. Нет ни секрета, ни дайджеста, ни key id (key id
меняется при ротации; `patId` - нет).

### Шаблон сканера

`src/main/resources/ru/ludwigandreas/pat/pat-secret-detection.properties` содержит регулярное выражение для
обнаружения, префикс для дешёвого предфильтра и готовое тело правила `gitleaks`.

Не применяется. События жизненного цикла токенов пишет `pat-spring-boot-starter` (категория `credential`).

## Runbook

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Токен `lpat_` появился в репозитории или логе | Утечка | Немедленно отозвать через API управления (`DELETE /api/v1/personal-access-tokens/{id}`), затем сменить всё, к чему он имел доступ |
| Токены неверного префикса или формы отклоняются как malformed | Опечатка или обрезка (проверка CRC32C) | Ожидаемо; клиент должен использовать токен ровно в выданном виде |

## Тестирование

`PatTokenFormatTest` проверяет сотни случайных образцов (круговой разбор должен проходить для каждого);
сравнение дайджестов - за постоянное время; у ослабления есть рефлексивный тест «нет расширяющего метода».

## Проектные решения

- **Ноль зависимостей**, потому что обеим сторонам шва безопасности нужно одно определение `ludwig_pat`.
  Литерал, написанный дважды, отказывает в открытую сторону: claim с опечаткой читается как «нет PAT», и токен
  получает все права владельца.
- **SHA-256, а не bcrypt/Argon2.** KDF защищает низкоэнтропийные человеческие секреты; здесь 43 символа base62 из
  `SecureRandom`. KDF добавил бы десятки миллисекунд каждому обмену. **Это рассуждение зависит от генератора**:
  если секрет станет короче или будет выбираться человеком, оно перестанет быть верным (указано у `PatDigest`).
- **Контрольная сумма CRC32C - не мера безопасности.** Она отсекает опечатки и обрезку без запроса к БД; подделку
  останавливает сравнение дайджестов.
- **Случайные части - base62**, а не base64url: в base64url есть разделитель `_`. Алфавит сужен, а не символы
  заменены, поэтому распределение остаётся равномерным.
- **Оставлено другим**: хранение, выпуск, ротация, отзыв и обмен (pat-стартер); пересечение с типизированными
  правами (security-стартер); проверка scope при выпуске (выпускающий); отрисовка отказа (граница сети).
