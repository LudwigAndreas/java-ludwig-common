# outbound-token-core

*[English](README.md) · **Русский***

Единственная реализация учётных данных, которые отправляет исходящий клиент, общая для
[`rest-client-spring-boot-starter`](../rest-client-spring-boot-starter) и
[`grpc-client-spring-boot-starter`](../grpc-client-spring-boot-starter): кэшируемый машинный токен, получаемый
один раз сколько бы вызывающих он ни понадобился, получение токена по OAuth2 client credentials и bearer-токен
вызывающего для ретрансляции.

| | |
|---|---|
| Роль | library |
| Зависит от (в репозитории) | ничего |
| Используется | стартерами `grpc-client`, `rest-client` |
| Поверхности | исходящий вызов эндпоинта токенов OAuth2 (через minter) |

## Использование

Модуль используют клиентские стартеры; сервис обычно не зависит от него напрямую.

```xml
<dependency>
    <groupId>ru.ludwigandreas</groupId>
    <artifactId>outbound-token-core</artifactId>
</dependency>
```

| Тип | Что это |
|---|---|
| `CachingTokenSource` | Машинный токен, кэшируемый до `skew` перед истечением, получаемый **один раз**, сколько бы вызывающих одновременно ни нуждались в новом (single-flight), и повторно получаемый при принудительном обновлении после отказа партнёра - без второго получения для вызывающих, отклонённых в тот же момент. Блокирующий `get(force)` и неблокирующий `getAsync(force)` |
| `CachedToken` | Токен и его срок. Токен без указанного срока считается уже истёкшим |
| `ClientCredentialsTokenMinter` | Грант OAuth2 client credentials для `spring.security.oauth2.client.registration`, опционально с суженными scope. Отказ - `TokenMintingException` с именем регистрации и кодом ошибки OAuth2, никогда не с учётными данными |
| `InboundBearerToken` | Bearer-токен обслуживаемого запроса для ретрансляции: `current()` из security-контекста или `of(authentication)`. `null`, если его нет |

Каждый клиентский стартер сохраняет транспортно-специфичное: как прикрепляется токен (HTTP-заголовок, gRPC
`CallCredentials`), счётчики, ключи конфигурации и исключения.

## Конфигурация

Собственной нет. Источники токенов настраиваются в блоке `auth` каждого клиента клиентских стартеров, а minter
использует стандартные свойства `spring.security.oauth2.client.registration.<id>.*` / `provider.<id>.*`.

## Развёртывание

Эндпоинт токенов OAuth2 каждой регистрации должен быть доступен; секреты клиентов попадают из хранилища
секретов в `spring.security.oauth2.client.registration.<id>.client-secret`.

Зависимости: обязательна только `slf4j-api`. `spring-security-oauth2-client` (minter) и
`spring-security-oauth2-resource-server` (чтение для ретрансляции) опциональны.

## Наблюдаемость

Здесь нет: счётчики обновления токенов публикуют клиентские стартеры (`ludwig.restclient.*`,
`ludwig.grpcclient.auth.token.refreshes`).

## Аудит

Не применяется. Исходящие вызовы аудируют клиентские стартеры (категория `outbound-call`).

## Runbook

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `TokenMintingException` с регистрацией и `invalid_client` | Неверные client id/secret | Исправить учётные данные регистрации в хранилище секретов |
| `TokenMintingException` с `invalid_scope` | Суженные scope не выданы клиенту | Выдать scope на сервере авторизации или сузить меньше |
| Вызовы падают с 401 сразу после ротации токена | Партнёр отвергает закэшированный токен | Обрабатывается: 401 вызывает одно повторное получение. Если не проходит - отвергается сам полученный токен; проверить audience и scope |
| Ретрансляция не отправляет токен | Нет входящего bearer-токена (планировщик, Kafka listener) | Использовать для этого клиента машинный токен вместо ретрансляции |

## Тестирование

`CachingTokenSourceTest` (single-flight, skew, принудительное обновление, отсутствие срока),
`ClientCredentialsTokenMinterTest`, `InboundBearerTokenTest` и `ModuleIndependenceTest` (ни одного типа
платформы). В каждом клиентском стартере есть `TokenOwnershipTest`, который падает, если там появится второй
кэш, minter или reader.

## Проектные решения

- **Отдельная библиотека**: в любом из стартеров она затянула бы транспорт другого (три HTTP-движка в gRPC-клиент
  или gRPC в REST-клиент).
- **Нет срока - значит истёк**: «никогда не истекает» - так отозванный токен используют неделями.
- **Без зависимостей в репозитории**, обеспечивается `ModuleIndependenceTest`.
